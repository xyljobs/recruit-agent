# Boss 结构化简历与 candidate-analysis 报告方案

## 1. 目标与结论

本项目采用以下默认方案：

1. 只通过 `assets/boss.py` 和 cloakbrowser 访问 Boss 直聘，所有候选人顺序处理，禁止并发。
2. 点击候选人卡片时保存 Boss 当前返回的结构化简历数据，并转换为可搜索的 `resume.txt`。
3. 用户在 Web 页面中直接预览、复制、搜索或下载自包含 HTML 简历；截图仅作为结构化数据不可用时的备份。
4. 报告严格使用 `candidate-analysis 0.2.0` 的六维结构和原版 HTML 模板。
5. 默认在 Mac mini 本地分析，不把完整简历发送到外部模型。外部 AI 分析必须另行评估合规性并显式授权。

这比“只保存截图、再在 Mac 桌面弹报告窗口”更适合当前远程使用场景：Windows 浏览器可直接访问，文本可检索，报告可在线查看和下载，同时保留截图证据。

## 2. candidate-analysis 技能落实情况

项目已经按技能约束落实以下内容：

- Boss 操作入口：`assets/boss.py`
- 顺序采集：同一时刻只处理一个候选人
- 原始模板：`assets/candidate_analysis/report_template.html`
- 原始渲染器：`assets/candidate_analysis/render_report.py`
- 六维评分：硬性匹配、技术深度、业务经验、职业轨迹、稳定性、综合潜力
- 推荐等级：`strong`、`rec`、`maybe`、`no`
- 报告模块：批次画像、六维对比矩阵、Top 推荐、候选人详情、雷达图、职业时间线、市场观察
- 报告中“查看简历”跳转到本系统鉴权后的原文预览，不再依赖 Mac 桌面窗口

## 3. 数据流与文件

每个任务目录结构如下：

```text
简历/<任务目录>/
├── manifest.json
├── analysis.json
├── report.html
└── <关键词目录>/<候选人目录>/
    ├── resume_source.json   # Boss 当前响应的结构化源数据，仅服务端保存
    ├── resume.txt           # 规范化、可检索的简历正文
    └── 01.png ...           # 截图备份
```

Web 端通过鉴权接口提供：

- 在线简历：原生 HTML 文本预览，可选择、复制、浏览器内搜索和打印
- 下载简历：下载自包含 HTML，不依赖截图或外部资源
- 在线报告：直接返回技能模板生成的 `report.html`
- 下载报告：下载同一份技能报告 HTML

所有任务、候选人索引和文件路径都经过服务端校验；浏览器不能提交任意磁盘路径。

## 4. 本地分析与外部 AI

### 默认：本地规则分析

`CANDIDATE_REPORT_MODE=local` 是默认值。它在 Mac mini 本地读取 JD 和简历，按技能六维模型完成：

- JD 技术词命中与缺口
- 经验、学历、地域等硬性要求
- 架构和项目证据
- 业务领域吻合度
- 工作经历时长和稳定性
- 技术广度、云原生及多语言潜力

优点是简历不出 Mac mini、结果稳定、成本低；限制是对隐含语义、项目真实性和复杂业务价值的判断不如大模型，报告中的风险项仍需人工面试核验。

### 可选：外部 AI 分析

只有同时配置以下两项时才允许发送完整简历到外部模型：

```dotenv
CANDIDATE_REPORT_MODE=external_ai
ALLOW_EXTERNAL_RESUME_ANALYSIS=true
```

启用前必须确认候选人授权、公司隐私制度、模型服务商的数据留存和训练政策、传输区域以及访问审计。仅配置 API Key 不代表已经获得简历外传授权。

### 推荐的下一阶段：Mac mini 本地模型

Mac mini M4 可部署本地模型（例如通过 MLX 或 Ollama），由 Worker 调用本机回环地址。这样能提升语义分析质量，同时避免向第三方传输简历。落地时应增加模型版本固定、JSON Schema 校验、超时和规则评分回退。

## 5. 旧任务补采和重新生成

旧任务不能直接复用过期的 `geek_url`，因为 Boss 可能返回其他默认候选人。补采必须重新搜索关键词，并按卡片 `expect_id` 精确定位，同时校验响应中的脱敏姓名和 `expect_id`：

```bash
cd ~/servers/zhipin-agent/assets
uv run --frozen boss.py hydrate "简历/<任务目录>"
```

本地重新生成技能报告：

```bash
CANDIDATE_REPORT_MODE=local uv run --frozen boss_worker.py --report-task <任务ID>
```

如果任何候选人的姓名或唯一标识不一致，补采会失败且不会覆盖已有结果。

## 6. 其他实现方案比较

| 方案 | 原文质量 | 可下载/检索 | 稳定性 | 隐私 | 建议 |
|---|---:|---:|---:|---:|---|
| Boss 结构化响应快照 + 文本规范化 | 高 | 高 | 高 | 数据留在本机 | **当前采用** |
| 直接打开 Boss 原简历页面 | 最高 | 低 | 低，依赖登录态和临时链接 | 不新增副本 | 仅作人工复核入口 |
| 从简历浮层 DOM 提取 HTML | 中高 | 高 | 中低，页面改版易失效 | 数据留在本机 | 结构化接口缺失时回退 |
| 下载 Boss 提供的 PDF/Word 附件 | 最高 | 高 | 取决于平台是否提供 | 数据留在本机 | 平台明确提供附件时优先 |
| 截图 OCR 后生成文本 | 中低 | 中 | 中 | 数据留在本机 | 最后回退，不作为主数据源 |
| 截图画廊 | 视觉证据高 | 低 | 高 | 数据留在本机 | 只保留为取证备份 |
| 结构化 HTML 再导出 PDF | 高 | 高 | 高 | 数据留在本机 | 可作为后续交付格式，不替代源数据 |

报告分析实现也有三种选择：

1. 本地规则引擎：当前默认，隐私最好，解释稳定。
2. Mac mini 本地大模型：长期推荐，语义质量和隐私之间最均衡。
3. 获得授权的外部大模型：效果可能最好，但必须完成合规和数据保护评估。

## 7. 安全与运维要求

- `resume_source.json`、`resume.txt`、截图和报告均属于候选人隐私数据，不提交 Git，不放公共对象存储。
- 当前文件接口必须保持登录校验、任务归属校验、真实路径校验和符号链接防护。
- 下载的 HTML 只包含转义后的文本，不嵌入 Boss Cookie、接口 URL、API Key 或原始响应 JSON。
- 设置明确的数据保留期限，到期按任务目录精确清理；删除前确认不再用于招聘审计。
- 搜索、补采和登录只使用 `assets/boss.py`，不得用普通浏览器自动化替代。
