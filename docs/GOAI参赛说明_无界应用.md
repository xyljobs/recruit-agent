# 人才决策Agent · GOAI 无界应用赛道参赛说明

> 赛道：无界应用 Boundless Agents ｜ 提交截止：2026-08-16 ｜ 许可：Apache-2.0

## 一、参赛定位

人才决策Agent 是一款可私有部署的招聘决策副驾驶，面向工业制造等人力密集行业，将“职位标准 → 授权候选人导入 → 可解释排序 → 人工短名单决策 → 沟通准备 → 结果复盘”组织为一条可审计闭环。

当前实现采用**单一受控编排工作流**：业务状态机决定步骤和权限，规则评分恒定可用，经批准时才调用 LLM，本地知识工具与异步 Worker 执行受限任务，HR 保留最终决定权。它不是四个可自主规划的 Agent，也不主张存在开放式多 Agent 协作。

## 二、目标用户与问题

- 制造业招聘团队：PLC、电气自动化、工业机器人、设备维护等岗位要求专业，HR 需要把技能证据与缺失项快速交给业务负责人复核。
- 有私有部署要求的企业 HR：简历涉及个人信息，不能默认发送到公有云模型。
- 已有 ATS 或授权简历库的团队：需要补上可解释排序、人工覆盖留痕与结果校准，而不是替换整套 ATS。

本项目不再把访谈测算的耗时、准确率、回复率或成本降幅当作已实现效果。当前可复现量化证据仅限第十一节所述 IT 单岗位离线基线。

## 三、任务闭环

| 阶段 | 输入 | 系统动作 | 人工节点 / 输出 |
|---|---|---|---|
| 职位标准 | JD 或人工录入要求 | 规则解析；获批时可用 LLM 结构化 | HR 校对需求卡片 |
| 候选人导入 | 已授权简历、CSV/JSON、正式 ATS | 校验授权、加密敏感字段、建立可审计映射 | 入库回执 |
| 可解释排序 | 职位标准 + 候选人能力字段 | 规则预筛；获批时可做受约束深度分析 | 分数、证据、缺失信息、版本化置信度 |
| 短名单决策 | 排序结果 | 保存接受、补充或覆盖操作 | HR 决策与理由留痕 |
| 沟通准备 | 人工已接受的候选人 | 本地模板或获批模型生成沟通 brief | HR 审核后自行触达 |
| 结果复盘 | 联系、面试、Offer、录用、撤回、投诉等事件 | 追加记录、看板汇总、生成校准建议 | 管理员决定是否采用新权重 |

系统不自动拒绝候选人、不自动发 Offer、不自动录用，也不对第三方招聘平台执行参赛范围内的浏览器自动化。

## 四、实现边界

```text
HR 人工决策节点
       │ 接受 / 补充 / 覆盖并填写理由
       ▼
Next.js 受控编排层
  ├─ 职位标准处理：规则解析 + 可选 LLM 结构化
  ├─ 匹配工具：确定性评分 + 可选深度分析
  ├─ 沟通工具：本地知识库 + 可选生成
  ├─ AI 执行网关：rules_only / private_endpoint / approved_cloud
  └─ 异步任务：批量匹配、简历批处理、正式 ATS 写回
       ▼
Supabase / PostgreSQL
  ├─ 多租户 RLS、敏感字段加密、授权记录
  ├─ 短名单决策、结果事件、审计记录
  └─ calibration 建议与版本化权重
```

步骤由业务规则预定义，不声称具备模型自主选工具、长期记忆或开放式规划能力。参赛价值在于把模型、工具、人工责任和数据边界组合为能运行、能追责的完整应用。

## 五、AI 执行边界

- `rules_only`（默认）：不调用任何模型或外部知识服务。
- `private_endpoint`：仅允许企业私有 OpenAI 兼容端点。
- `approved_cloud`：只允许部署方批准的外部端点；还需每个租户管理员逐项批准处理器，未批准自动降级。
- 云端模式仅发送去标识化的结构化能力画像，不发送姓名、联系方式、公司名和原始简历。
- 扫描版 PDF 的外部视觉分析默认关闭，须另行取得候选人授权并由管理员显式开启。

## 六、数据来源与平台边界

参赛演示只使用以下来源：

1. 仓库内虚构 seed 数据。
2. 企业自有且已取得候选人授权的简历库。
3. 携带完整授权结构的 CSV/JSON。
4. 经过合同、权限和主机白名单确认的正式 ATS 接口。

仓库保留的实验性外部招聘平台浏览器自动化不属于参赛交付。默认 `ENABLE_BOSS_SEARCH=false`，页面、API 和命令行入口均拒绝运行；任何启用均以目标平台书面授权和独立法律审查为前提。

## 七、隐私与人工责任

- 姓名、邮箱、电话、当前公司、当前职位使用 AES-256-GCM 加密；HMAC 盲索引只支持精确查询。
- 候选人授权范围、时间和撤回操作留痕；撤回触发最强清理并生成回执。
- AI 分数只参与排序，HR 对接受、覆盖、触达、拒绝和录用负责。
- ATS 写回只允许精确 HTTPS 主机白名单，为空时拒绝所有外发。
- 结果事件追加保存，普通用户不能改写历史。

## 八、可运行与可复制

- Next.js 16、React 19、TypeScript strict、Supabase/PostgreSQL，支持 Docker 自托管。
- `pnpm db:migrate && pnpm admin:bootstrap && pnpm seed:demo` 可建立演示环境。
- 本地 Markdown 知识库可替换；行业迁移不要求绑定模型供应商。
- Apache-2.0 开源；直接依赖、可选外部服务和参赛排除项见《第三方依赖与发布边界》。

## 九、多模态能力

简历批处理可识别文本 PDF；扫描版 PDF 可经视觉模型结构化后进入同一闭环。外部视觉模型默认关闭（`ALLOW_EXTERNAL_RESUME_BATCH_ANALYSIS=false`），因此该能力在未授权部署中不会外发原始简历。

## 十、异常处理与证据

- AI 不可用或未获批：自动使用 `rules_only`，业务流程仍可继续。
- 异步任务：任务状态、租约、失败和重试均持久化。
- 数据库启动：缺少生产表时启动失败并给出迁移要求。
- 结果证据：匹配版本、结构化证据、缺失项、人工覆盖理由和业务结果可回溯。

## 十一、已完成的 IT 单岗位离线基线

当前唯一可对外引用的效果基线为：1 个真实在招 Java 职位、20 份真实授权且去标识化的简历、1 位资深 IT 招聘方三档标注。确定性评分器与人工排序 Spearman 相关系数为 **0.706**；人工强推候选人召回率 @5 为 **2/4**、@10 为 **4/4**。复现命令：

```bash
pnpm eval:match scripts/match-benchmark.java-real.json
```

该结果只能证明这一 IT 样本上的排序基线，不能证明制造业准确率、业务提效、成本下降或候选人回复率。完整限制见《评测报告_2026-08》；制造业正式评测尚待按《制造业评测方案》完成。

## 十二、当前达标判断

- **已具备**：完整可运行产品、私有部署、人工责任节点、数据治理、可解释排序、异常降级、离线基线、自动化测试与开源许可。
- **仍是主要风险**：制造业定位尚缺真实双标注评测；Demo 视频仍需按仓库脚本录制并提交；当前是受控工作流，不应包装为开放式多 Agent。
- **参赛口径**：提交“可审计招聘决策工作流”，不提交第三方平台浏览器自动化，不使用未经验证的商业指标。
