### 4.2 新建 `src/lib/matching/screening-rubric.ts`

- `screeningRubricSchema`（zod，全部字段可选，解析失败返回空 rubric 而非 throw）
- `parseExperienceBand(text: string)`：支持 `3-5年` / `3~5年` / `3年以上` / `5年以内` / `不超过6年` / `3到5年`；解析不出返回 `null`
- **`source` 判定规则**：JD 原文含 `以内 / 不超过 / 上限 / 最多` 之一 → `'explicit'`，`hard_max_enabled = true`；否则 → `'inferred'`，**`hard_max_enabled = false`**
- `scoreExperienceBand(band, years)` 返回 `{ score, hard_constraints, boundary_flags }`：

| 情况 | score | 附加输出 |
|---|---|---|
| `band` 缺失 | 走原 `parseExperienceYears` 旧逻辑 | 无（向后兼容） |
| `years < min` | `max(20, round(years / min * 70))` | 无 |
| `min <= years <= preferred_max` | `100` | 无 |
| `preferred_max < years <= hard_max` | `max(70, 100 - (years - preferred_max) * 10)` | `boundary_flags: [experience_boundary]`，label `边界` |
| `years > hard_max` 且 `hard_max_enabled` | `60` | `hard_constraints: [{ code:'experience_over_hard_max', reason:'年限 {years} 年 > 岗位硬上限 {hard_max} 年' }]` |

### 5.1 迁移两表（追加 migrate.sql；RLS 策略与索引照抄 `communication_briefs` 写法）

**`interview_question_bank`**（用户提供的题库）

```
id uuid PK default gen_random_uuid()
organization_id uuid NOT NULL → organizations(id)
scope varchar(20) NOT NULL CHECK (scope IN ('organization','job'))
job_id uuid NULL → job_requirements(id)
  CHECK ((scope='job' AND job_id IS NOT NULL) OR (scope='organization' AND job_id IS NULL))

probe_followups jsonb DEFAULT '[]'
expected_signals jsonb DEFAULT '[]'

```

- 唯一索引防重复录入：`UNIQUE (organization_id, scope, COALESCE(job_id,'00000000-0000-0000-0000-000000000000'::uuid), md5(question))`
- `source` 用 CHECK 锁死为 `'user'`——**结构上保证公共题只能人工录入**


### 5.2 新建 `src/lib/recruiting/interview-guide.ts`

`interviewGuideContentSchema`（zod `strictObject`），字段：

```ts
{
  focus_areas: Array<{ dimension: string; why: string; must_verify: boolean }>,   // ≤6
  common_questions: Array<{ bank_id: string; question: string; dimension: string }>,  // ≤4
  targeted_questions: Array<{
    question: string;
    dimension: string;
    origin: 'evidence_gap' | 'depth_check' | 'boundary_risk' | 'resume_probe';
    expected_signals: string[];      // ≤3
    probe_followups: string[];       // ≤2
    scoring_anchors: string[];       // ≤3
  }>,                                 // 6–10
  red_flags_to_check: string[],       // ≤5
  interview_loop: Array<{ round: number; focus: string; minutes: number; interviewer_role: string }>, // ≤3
  prohibited_topics: string[],
}
```

- `PROHIBITED_INTERVIEW_TOPICS`：婚姻、生育/生育计划、年龄、户籍、籍贯、健康/病史、宗教、政治面貌、性取向、家庭财产
- `assertNoProhibitedTopic(text)`：命中则 `throw new ApiRequestError('面试题包含禁止询问的内容：{命中词}', 400)`；**题库录入与 AI 产出都必须过这道校验**
- `buildRulesOnlyInterviewGuide(input)`：专项题四来源（**这是"个性化"的实现主体**）

| origin | 触发条件 | 题目模板 |
|---|---|---|
| `depth_check` | `evidence_snapshot.support_level ∈ {partial, conflicting}` | `围绕「{finding}」，请具体说明你负责的部分、技术决策依据和最终量化结果` |
| `evidence_gap` | `match_details.gaps[]` / `missing_information[]` | `请补充说明：{gap}；并举一个可核验的实例` |
| `boundary_risk` | `match_details.constraint_analysis.boundary_flags[]` | 年限边界 → `你目前的年限与岗位定位存在差异，请说明你对该岗位职责范围与发展预期的理解`；频繁跳槽 → `请说明近两次变动的原因与决策过程`；跨城 → `请说明到岗时间与长期工作地安排` |
| `resume_probe` | `resume_text` 中的项目条目（**仅 AI 模式**） | 由 LLM 生成针对具体项目的追问 |

生成后按 `depth_check → evidence_gap → boundary_risk → resume_probe` 排序，去重，截断到 10 条；不足 6 条时用 `focus_areas` 补通用深度题。

- `parseModelInterviewGuide(value)`：JSON 提取逻辑。`communication-brief.ts` 的 `extractJsonObject`(L89) 是私有函数 → **提取到 `src/lib/ai/json.ts` 共用**，并改 `communication-brief.ts` 引用它，**保持 `communication-brief.test.ts` 全部通过**
- 🔒 **公共题原文不可改写**：公共题**不进入 LLM prompt 的可改写区**，只在输出阶段按 `bank_id` 从数据库拼回。必须有单测锁定：`output.common_questions[i].question === bank[i].question` 严格相等
- `canPrepareInterviewGuide(snapshotDecision, latestEventDecision)`：仿 `canPrepareCommunicationBrief`，允许 `accepted` 与 `overridden`（口径 1 要求覆盖后可推进），双重校验快照与最新事件一致
