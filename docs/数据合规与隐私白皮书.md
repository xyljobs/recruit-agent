# 智聘Agent 数据合规与隐私白皮书

> 版本：2026-08 ｜ 适用范围：智聘Agent 开源发行版 ｜ 法律依据：《个人信息保护法》《数据安全法》《网络安全法》

本白皮书说明智聘Agent 在候选人个人信息处理上的设计原则、技术控制与合规披露。合规不是事后补充，而是系统架构的起点：默认不调用模型（`rules_only`），任何向外部发送数据的能力都必须经过显式审批且仅发送去标识化载荷。

## 一、设计原则

1. 数据不出域：私有部署，每个组织独立租户，行级安全（RLS）隔离。
2. 最小必要：仅处理招聘决策必需字段；AI 载荷去标识化。
3. 知情授权：候选人授权范围、时间、撤回全留痕。
4. 人工负责：AI 只排序不决策；拒绝/录用等决定由人作出并留痕。
5. 默认可审计：结果事件追加保存，普通用户不可改写历史。

## 二、数据来源合规

| 来源 | 合规控制 |
|------|----------|
| 企业自有简历库（官网/内推/招聘会） | CSV/JSON 导入必须携带完整 authorization 结构，缺授权拒收；敏感字段入库前加密 |
| 候选人主动授权录入 | 授权记录含范围与时间戳；支持拒绝自动化匹配（无需 PIA 链接即可拒绝） |
| 部署方自有平台账号（Boss 直聘） | 见第六节专项说明 |

## 三、数据分类与加密

- 敏感字段（姓名、邮箱、电话、当前公司、当前职位）：AES-256-GCM 加密存储，密钥经 `ENCRYPTION_KEY` 注入，数据库管理员无法直接查看明文。
- 检索索引：HMAC-SHA256 盲索引支持精确匹配查询，不暴露明文，不支持模糊搜索（有意的隐私取舍）。
- 非敏感字段（技能、年限、学历、意向城市等）：明文存储用于规则评分。
- 密钥管理：Docker 部署经 secrets 文件注入，不与业务配置混放。

## 四、AI 执行边界

三档执行模式（`AI_EXECUTION_MODE`）：

1. `rules_only`（默认）：不调用任何模型或知识服务。
2. `private_endpoint`：企业私有 OpenAI 兼容端点，数据留在企业边界内。
3. `approved_cloud`：经批准的外部端点；载荷去标识化——不含姓名、联系方式、公司名、原始简历与工作经历，仅发送结构化技能/年限/学历/薪资区间等字段。

双重审批：部署模式只是能力上限；每个租户须由管理员在"数据源"页逐项批准 `approved_cloud_processors`，未批准自动降级。自动化匹配辅助另需影响性评估（PIA）证据链；候选人可单独拒绝自动化匹配而不影响人工流程。

## 五、候选人权利

- 知情与授权：录入即记录授权范围与时间。
- 撤回权：一键撤回触发最强清理（加密字段、索引、关联记录），生成删除确认回执。
- 拒绝自动化：可拒绝 AI 匹配辅助，系统保留人工流程。
- 决策权配置：组织可为候选人配置决策参与权利（decision-rights）。
- 权利请求处理：`candidate-rights-requests` API 支撑查阅/更正/删除请求的登记与办理 SLA，看板公示隐私处理时效。

## 六、Boss 直聘接入专项说明

定位与边界：

- 该能力是**部署方自有账号的本地辅助工具**：HR 本人在自己机器上扫码登录自有账号，登录态由 HR 持有；Worker 运行在部署方本地环境，任务经租约机制认领。
- 系统不集中存储平台账号凭证，不代运营、不集中爬取；搜索关键词由 HR 触发，结果仅写入部署方自有数据库。
- 云端（Web 应用）只负责任务入队、状态展示与报告呈现，不在服务端读取本地文件或启动进程。

风险披露：

- 该模式依赖招聘平台服务条款对自动化工具的态度，存在平台政策风险。产品侧已做三项缓释：人授权（HR 本人登录）、本地跑（数据与执行不出部署方环境）、可审计（任务状态机全程留痕）。
- 集成层（integrations）已预留官方 API 接入位；若平台开放官方渠道，可平滑替换 Worker 链路。
- 对平台自动化持保守态度的组织，可仅使用"自有简历库 + 简历批处理"闭环，Boss 链路为可选组件，不启用即零暴露。

## 七、访问控制与出站治理

- 认证：应用层 JWT 会话 + 可选 MFA（TOTP）；登录限流；首登强制改密。
- 授权：组织级 RBAC；数据库 RLS 双保险；服务端签发短期 RLS 令牌（`SUPABASE_JWT_SECRET`）。
- 出站：ATS 写回与 webhook 目标主机必须精确列入 `INTEGRATION_OUTBOUND_ALLOWED_HOSTS`，为空全部拒绝；外部调用只由 Worker 异步执行，与业务事务解耦。

## 八、留存与删除

- 结果事件（触达/回复/面试/录用/撤回/投诉）追加保存，支撑审计与校准。
- 授权撤回执行最强清理：敏感字段密文、盲索引、关联匹配记录一并删除，保留不可识别的统计占位（如看板零分母"待积累"）。
- 演示数据（seed）与生产数据分离；生产容器不因残留环境变量自动写入演示数据。

## 九、合规披露清单（供评审与部署方核对）

- [ ] 已明示候选人授权范围与撤回路径
- [ ] 已配置加密与 HMAC 密钥（64 位 hex，独立生成）
- [ ] AI 执行模式与租户审批状态与组织合规要求一致
- [ ] 出站白名单已按集成需求最小化配置
- [ ] Boss 链路启用与否已由部署方书面确认
- [ ] 自动化辅助启用前已完成 PIA 证据登记

## 十、已知限制与后续工作

- 知识库为本地分块检索，不含候选人个人信息，无外部检索服务暴露面。
- 扫描版 PDF 视觉解析默认关闭；启用外部模型时需另行完成去标识化与审批配置。
- 校准（calibration）输出为建议，权重变更需管理员批准并版本化，可回滚。
