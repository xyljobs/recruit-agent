# 智聘Agent 数据合规与隐私白皮书

> 版本：2026-08 ｜ 适用范围：GOAI 参赛交付与默认开源部署 ｜ 本文不是法律意见

本白皮书说明候选人个人信息处理的产品边界。系统默认不调用模型（`rules_only`），AI 只辅助排序，任何拒绝、触达、Offer 或录用决定均由授权人员作出。

## 一、设计原则

1. 私有部署与租户隔离：每个组织通过 PostgreSQL RLS 隔离。
2. 最小必要：只处理招聘任务需要的字段，外部模型载荷去标识化。
3. 先授权后处理：记录授权范围、时间、来源与撤回。
4. 人工负责：AI 不自动拒绝、发 Offer 或录用。
5. 默认拒绝外发：未经审批的模型、ATS 主机和浏览器自动化均不可用。

## 二、参赛允许的数据来源

| 来源 | 控制 |
|---|---|
| 仓库 seed 数据 | 全部为虚构演示数据，不映射真实个人 |
| 企业自有简历库 | 必须有候选人授权或其他合法处理基础，导入时保存授权结构 |
| CSV / JSON | 新候选人缺少完整 `authorization` 时拒绝入库 |
| 正式 ATS 接口 | 先确认合同、权限和数据用途；写回主机须进入精确 HTTPS 白名单 |

外部招聘平台浏览器自动化不属于参赛数据来源。默认 `ENABLE_BOSS_SEARCH=false`，页面、API 和命令行均返回禁用；任何启用必须先取得目标平台书面授权并完成独立法律审查。

## 三、数据分类与加密

- 姓名、邮箱、电话、当前公司、当前职位：AES-256-GCM 加密存储。
- HMAC-SHA256 盲索引：只支持精确匹配，不支持模糊检索。
- 技能、年限、学历和意向城市：为匹配所需的结构化字段，按组织权限读取。
- 密钥：通过环境 Secret 注入，`ENCRYPTION_KEY`、`HMAC_KEY`、`JWT_SECRET` 相互独立。

## 四、AI 执行边界

| 模式 | 默认 | 数据边界 |
|---|---|---|
| `rules_only` | 是 | 不调用模型或外部知识服务 |
| `private_endpoint` | 否 | 仅企业私有 OpenAI 兼容端点 |
| `approved_cloud` | 否 | 部署级允许 + 租户管理员逐项批准；只发送去标识化能力画像 |

去标识化载荷不含姓名、联系方式、公司名和原始简历。扫描版 PDF 的外部视觉处理可能包含原始简历图像，因此另设 `ALLOW_EXTERNAL_RESUME_BATCH_ANALYSIS=false`，只有取得相应授权并完成供应商评估后才可开启。

## 五、候选人权利与人工决策

- 支持知情、查阅、更正、撤回和删除请求登记。
- 授权撤回触发敏感字段、盲索引与关联记录的最强清理，并生成回执。
- 候选人可以拒绝自动化匹配辅助而保留人工招聘流程。
- 每条短名单结论保存 HR 的接受、补充或覆盖理由；模型输出不能替代该记录。

## 六、访问控制与出站

- 应用 JWT 会话、可选 TOTP MFA、登录限流和首登强制改密。
- 组织级 RBAC 与数据库 RLS 双层授权。
- ATS 写回通过事务 outbox 异步执行；目标主机必须精确列入 `INTEGRATION_OUTBOUND_ALLOWED_HOSTS`，为空时全部拒绝。
- Webhook、模型与可选 MCP 服务须分别完成最小权限配置，不共享长期管理员凭证。

## 七、留存、审计与事故响应

- 结果事件追加保存，普通用户不可覆盖历史；校准只生成建议，权重变更由管理员批准并版本化。
- 部署方应设定候选人数据留存期限、备份期限和删除后的备份淘汰周期。
- 发现误配置外发、越权访问或密钥泄露时，应立即关闭对应处理器、轮换密钥、保存审计证据并按适用法律评估通知义务。

## 八、部署验收清单

- [ ] 数据来源、授权文本和处理目的已经业务与法律负责人确认
- [ ] 加密、HMAC、JWT 与 Supabase JWT 密钥独立生成并安全注入
- [ ] `AI_EXECUTION_MODE` 与租户审批状态符合组织政策
- [ ] 扫描件外部分析保持关闭，或已有单独授权和供应商评估
- [ ] ATS 出站白名单最小化，未使用的集成保持关闭
- [ ] `ENABLE_BOSS_SEARCH=false`，参赛演示不存在第三方平台自动化
- [ ] 已定义留存、撤回、删除、备份淘汰和事故响应责任人

## 九、已知限制

- 技术控制不能替代合法处理基础、隐私告知、供应商合同或影响评估。
- 本地 Markdown 检索不是向量检索，知识库规模增大后需重新评估准确性和访问控制。
- 当前离线基线不足以证明公平性；在制造业正式样本中还需按性别、年龄等敏感维度进行合法、最小化的偏差审计。
