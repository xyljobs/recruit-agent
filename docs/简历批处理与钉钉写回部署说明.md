# 简历批处理与钉钉写回

该功能将批量 PDF 上传、简历文本提取、扫描件视觉识别、AI 推荐理由生成和钉钉表格写回整合到人才决策Agent。

## 架构

1. HR 在 `/resume-batch` 粘贴钉钉表格链接并上传 PDF。
2. Next.js 将 PDF 放入私有 Supabase Storage，并创建 `resume_batch_tasks` 任务。
3. 本地 `resume_batch_worker.py` 领取任务，依次验证同一租户的加密 MCP 凭证，自动识别表格所属组织。
4. Worker 临时下载 PDF，读取钉钉表格并按“PDF 文件名 = 姓名”匹配候选人。
5. 文本型 PDF 直接提取；文本不足时使用视觉模型识别。
6. Worker 并发生成推荐理由，将连续行合并写回“推荐理由”列；批量失败时自动回退逐格写入，试运行模式不写表。
7. 任务结束后立即删除私有 Storage 中的原始 PDF。

MCP URL 和管理员保存的模型 API Key 使用项目现有 `ENCRYPTION_KEY` 进行 AES-256-GCM 加密。员工不能读取 MCP URL 或模型密钥。

## 一、数据库升级

在项目根目录执行：

```bash
pnpm db:migrate
```

迁移会创建：

- `resume_batch_credentials`
- `resume_batch_settings`
- `resume_batch_sheets`
- `resume_batch_tasks`
- 私有 Storage Bucket `resume-batch-files`

如果 Storage Bucket 未在迁移时创建，首次上传会使用 service role 凭证自动创建。

## 二、环境变量

根目录 `.env.local` 至少需要：

```dotenv
SUPABASE_URL=http://localhost:8000
SUPABASE_SERVICE_ROLE_KEY=<service-role-key>
LLM_API_KEY=<模型 API Key>
LLM_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
LLM_MODEL=qwen-plus
RESUME_VL_MODEL=qwen-vl-max
PIPELINE_WORKERS=8
ENCRYPTION_KEY=<与网站现有配置一致的64位hex>

# 原始简历文本会发送给模型。确认候选人授权与公司数据政策后显式开启。
ALLOW_EXTERNAL_RESUME_BATCH_ANALYSIS=true
```

未显式设置 `ALLOW_EXTERNAL_RESUME_BATCH_ANALYSIS=true` 时，Worker 会拒绝处理任务。

## 三、安装并启动 Worker

简历 Worker 与 Boss Worker 共用 `assets/.env.worker`：

```bash
cd assets
cp .env.worker.example .env.worker
uv sync
pnpm add -g mcporter
uv run resume_batch_worker.py
```

Windows 可用 PowerShell：

```powershell
Set-Location assets
Copy-Item .env.worker.example .env.worker
uv sync
pnpm add -g mcporter
uv run resume_batch_worker.py
```

单次处理一个任务后退出：

```bash
uv run resume_batch_worker.py --once
```

Mac mini 常驻运行可安装仓库内的 launchd 配置：

```bash
cp scripts/com.zhipin.resume-batch-worker.plist \
  ~/Library/LaunchAgents/com.zhipin.resume-batch-worker.plist
launchctl bootstrap gui/$(id -u) \
  ~/Library/LaunchAgents/com.zhipin.resume-batch-worker.plist
```

`.env.worker` 中必须配置与 Web 应用相同的 Supabase 与加密密钥：

```dotenv
WORKER_SUPABASE_URL=http://localhost:8000
WORKER_SUPABASE_KEY=<service-role-key>
ENCRYPTION_KEY=<与根目录完全一致>
```

Worker 会继续从根目录 `.env.local` 读取 `LLM_*`、`PIPELINE_WORKERS` 和授权开关。管理员页面保存的模型配置优先于环境变量。

## 四、管理员首次配置

1. 使用管理员账号打开 `/resume-batch`。
2. 切换到“管理员配置”。
3. 使用目标组织账号登录 `https://mcp.dingtalk.com`，创建“钉钉表格” MCP。
4. 为每个需要访问的钉钉组织添加一条 MCP 凭证。URL 保存后不会再次完整回显。
5. 按需配置模型、并发数和推荐理由参考范例，并使用“测试连通性”验证。
6. 员工粘贴任一已授权表格链接后，Worker 会自动选择可访问该表格的组织凭证。
7. 目标表格必须包含“姓名”列；建议明确创建“推荐理由”列，否则默认写入 H 列。

## 五、使用与验收

1. 粘贴测试表格链接，选择 1–2 份测试 PDF，文件名改成表格内姓名。
2. 勾选“试运行”，确认推荐理由与匹配结果。
3. 取消试运行，正式写回。
4. 在钉钉表格确认目标单元格内容。
5. 在任务日志确认出现“原始 PDF 已从私有临时存储删除”。

## 故障排查

- 一直显示“等待 Worker”：确认 `resume_batch_worker.py` 正在运行，且 Supabase 地址和 service role key 正确。
- 所有凭证均无权限：用表格所属钉钉组织重新生成 MCP URL，并在管理员配置中添加或轮换凭证。
- 扫描件失败：确认 `RESUME_VL_MODEL` 支持图片输入。
- 模型调用被拒：确认 `LLM_API_KEY`、模型名称以及 `ALLOW_EXTERNAL_RESUME_BATCH_ANALYSIS=true`。
- 没有匹配人员：PDF 文件名必须与表格“姓名”列一致。
